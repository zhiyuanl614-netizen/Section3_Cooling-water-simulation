### 关键改动

**① 分层声明并入耦合架构 2.2.1** —— 三种时间尺度写进方法（原独立 2.1 节取消，问题设定归引言）：

| 层 | 步长 | 求解内容 | 代码位置 |
|---|---|---|---|
| 冷端 | 1 s | 水位/流量/温度/背压演化 | `model.simulate` |
| 频率 | 0.01 s | SFR 积分、调速器、AGC、UFLS | `coupled.simulate_frequency_ramp` |
| AC 断面 | 事件驱动 | 孤岛分解、潮流、保护判据 | `cascade.CascadeSim` |

明确写出：**这不是单一时间步长的暂态联合仿真**；AC 电压只在事件断面求解。

**② 2.3 升格为全文重心** —— 形式化核心闭环反馈：

```
冷端保护触发 → 机组跳闸 → 网侧再调度 → 幸存机组 Pg 改变
    → 冷端耗水率改变 → 跳闸时刻改变 → 下一轮再调度
```

**③ 2.2 按物理链条组织** —— 严格对应 `model.simulate` 循环顺序：

```
池水位 → 泵可用流量 → 塔出口水温 → 凝汽器(UA-LMTD+蓄热) → 背压
     → 汽轮机热力能力 → 运行员SOP → 保护判据
```

保护判据顺序（代码实现）：低水位 → 汽蚀下限 → 低真空（含延时）→ 技术最小

**④ 2.4 纳入收敛性审计** —— 说明收敛性约束切负荷/频率等次级量；**H=F3 为拓扑判定，不依赖求解器**

**⑤ 2.5 前移边界声明** —— 减少审稿人"被误导后被拒绝"的风险

## 3.3 冷端机组子集的选取（3.1.2，新增节）

**三条论证**：

## 3.4 情景设计

### 物理背景（已定稿）
- 六台机组位于**同一地区**，冷端补水取自**同一 regional 水源**
- 失效机制为**机组自身补水管线故障**（管道破损 / 阀门失效 / 泵组故障 / 控制失电）
- **一台机组故障不影响同区其他机组取水**；多机情景 = 多起独立机组级故障
- **必须声明**：本研究**未模拟"水源本身断供"的共因情景**

## 5.3 各节要点

### 5.1 机理建模的信息增量
论证为什么不能只用"固定降额率 + 固定延时"表示冷端失效。核心证据即上述 28 个记录到 G1 跳机时刻的组合（提前 9.9–45.4%）。

### 5.2 耦合机制的解释
**关键论点**：**第二次跳机的时间由第一次跳机的网侧后果决定**，而非冷端独立演化。若忽略跨域反馈，用 K1 独立跳机时刻（13.71 h）推算，将**完全错过** 5.08 h 时的硬失供。

**组合结构解释**：核验显示 H>0 与"组合含 G1"并非完全等价（精确口径：32 案含 G1 中 18 案 H>0；不含 G1 的 31 案中 4 案 H>0，均含 G13+G22+G23 且仅 H=2，故全部 H>2 案均含 G1——**枚举观察，非预设假设**）。G2 占系统负荷 32.2%（最大单机）、G1 与 G2 电气相邻（B1–B2），两者同时断水时缺额叠加且再调度路径受限。

**必须诚实说明**：
1. 这**不是**"组合效应"，也**不是**"主导机组对效应"——
   22 个 H>0 情景涉及 22 种互不相同的组合，不存在重复的主导机组对；
2. **严重失供（H>2）的 14 案全部含 G1（枚举观察）**：含 G1 的 5 个 2 机组合中仅 G1+G2 一案级联；
3. **存在无法分离的混杂性**：G1 同时是**平衡机（1 号母线）**、
   **初始出力最低（23.54 MW，装机率 29.4%）**、**可用库容最大（系数 1.20）**，
   三种机制在本算例中不可分辨，不得判定何者为主因；
4. 65% 无级联的主因是备用充裕（77.1%）。

### 5.3 与既有研究的关联
- **与冷端失效研究**：既有研究多聚焦单机组失效机理与现场事故复盘；本文增量在于把冷端机理作为级联分析的输入
- **与级联失效研究**：经典 N−k 分析假设故障与机组物理属性**解耦**；本文表明对冷却水类故障，**扰动幅度是内生的**——这与"相依失效（dependent failures）"文献呼应

### 5.4 实践启示

以下均为**基于单一算例的定性推论**，不可写成运行建议：

1. **冷端状态监测的电网价值**：应关注"本机组跳机对邻机冷端的连带影响"（通过 $P_g$ 变化传导）——传统监测只看本机组何时跳机
2. **组合风险不能按台数线性估计**：G1 单独 H=0，与 G1+G2 组合 H=23 相差悬殊
3. **再调度路径的重要性**：G1/G2 电气相邻导致后果严重；再调度可行性应纳入冷端约束
4. **相邻机组组合的防护优先级**：同水源、同区、相邻电气位置的组合应作为重点

### 5.5 模型局限性与后续研究工作

#### 5.5.1 模型适用条件的限制

| 局限 | 具体表现 |
|---|---|
| **单一算例** | 仅 IEEE30（30 母线／6 冷端机组），旋转备用 77.1% 属宽松运行点；结论不外推其他系统规模 |
| **冷端子集不完整** | IEEE30 原生 10 台发电机中仅 6 台配置冷端锚点，另 4 台（B5/B8/B29/B30）未纳入 |
| **准稳态断面级联** | 非电磁暂态仿真；秒级电压轨迹不被连续计算；保护定值为研究设置，非现场继电保护整定值 |
| **未模拟水源共因失效** | 现设定为区域共水源 + 机组侧补水管线故障；真正的水源断供共因情景不在枚举集内 |
| **参数未实测** | 爬坡率、再调度延时、补水响应时间常数、UFLS 延时、$H_{sys}$、下垂系数均为参考假设或研究设置 |
| **确定性情景研究** | 63 案为规定情景集的枚举占比，**非概率估计**，不可外推故障率或风险指标 |

#### 5.5.2 数值条件的限制

| 局限 | 具体表现 |
|---|---|
| **收敛性未证明** | K4-G1-G2-G13-G22（60 条奇异告警，H=25）与 K5-G1-G2-G13-G22-G27（120 条，H=29）的潮流求解内部收敛性未获证明；H=F3 为拓扑判定不受影响，但两案的切负荷/频率等次级量为**条件性结果** |
| **文件级审计的局限** | 已归档 CSV 通过 NaN/Inf 文件级审计，但这不等于内部潮流迭代收敛性得到证明 |
| **数值失败端点（F2b）披露** | F2b 已从判据中移除，作为求解器数值失败端点披露；其不可行性未用 CPF/HELM 作算法无关确认 |

#### 5.5.3 后续研究方向

由上述局限自然导出的研究缺口，按优先级：

1. **消除数值病态并复算**：在孤岛求解前增加拓扑前置校验（过滤零注入母线、单母线孤岛直接判定、slack 排除已退出机组），消除奇异矩阵后重算全部 63 案，量化当前 H 值的数值敏感性
2. **收紧运行点至传输极限附近**：当前备用充裕导致 65% 情景无级联，判别力受限；提高负荷水平可使更多情景进入真实级联区间
3. **实施敏感性／鲁棒性分析**：爬坡率、再调度延时、支路过载阈值、UFLS 定值、负荷水平等均为未实测参考值，需检验结论对其的依赖程度
4. **扩展算例**：引入 IEEE39 或 IEEE118，检验"含 G1 才级联"的现象是否可迁移；
   需另选平衡机，使冷端裕度效应与平衡机身份解耦
5. **验证数值失败端点的不可行性**：构造重载／低备用算例，用 CPF/HELM 确认 F2b 端点（当前仅作披露，未作算法无关确认）
6. **实现母线断路器动作判据 $T_b$**：将 $H=1[F3]$ 扩展为 $1[F3\lor T_b]$，把硬失供判据由孤岛级提升至母线级
7. **补充水源共因失效情景**：按水源站分组注入故障，覆盖真正的共因路径
8. **引入消融／对照实验**：固定 $P_g$ 与耦合 $P_g$ 的对照，是支撑"跨域耦合效应"的最强证据（当前仅有 P5 与 K1 的天然对照）

### 核验过程中修正的两处错误

1. **跳闸机理表述错误（已修正）**。初稿将 K2-G1-G2 的跳闸标注为"水位耗竭"，
   核对 `cooling_demand_response.csv` 后发现**两台机组的水位均未耗尽**：
   - G2 在水位 **1.0999 m** 跳闸（初值 3.60 m）
   - G1 在水位 **0.9999 m** 跳闸（初值 4.20 m）
   
   跳闸由**固定阈值**触发，而非库容耗尽。全部图表与正文表述已改为"水位降至
   阈值"，**不得**使用"耗竭"。

2. **失供曲线不可用作时序面板**。`dispatch_trajectory.csv` 中的 `shed_mw`
   是 UFLS 切除量，本情景为 0；164.3 MW 来自 `static_grid_shed_mw`，是仿真
   **结束后**计算的静态结果，不存在于轨迹中。原设计的"切负荷随时间演化"
   面板因此恒为 0，已替换为**补水量需求时程**——后者才是本情景的真实驱动量。

### 补水平衡揭示的耦合证据

| 时点 | G1 补水量需求 (m³/h) | 事件 |
|---|---|---|
| t=0 | 71.7 | G1 出力 25.97 MW |
| t=4.66 h（G2 跳闸前） | 71.7 | G1 出力已升至 52.64 MW |
| t>4.66 h | **128.8** | G1 独自承担 G2 负荷，补水需求跃升 80% |

补水量供给自 t=0 起恒为 0。G1 跳闸时刻（9.7383 h）与冷端参数表中该算例的
G1 独立断水跳闸时刻（13.7061 h）之差，即为本次并发断水的净加速效应。

### 写作限制

1. 不得称 H=23 为"频率事件导致"——`f_nadir`=59.36 Hz，UFLS 未动作，
   F2a/F2b 均为 0，失供全部来自 F3 静态拓扑级联；
2. 不得将补水量需求跃升单独归因于"耦合"，因为 G1 在 G2 跳闸前的出力已由
   调频/AGC 抬升，该跃升同时包含调频与并发断水两种来源；
3. 9.7383 h 与 13.7061 h 的差是**净效应**，不等于纯冷端耦合效应。

# 第十五部分：机制论断的条件性审查与补强（2026-10-26）

## 触发问题

用户质疑：**"当前的失效判定结果均是拓扑无源的失效，请评估该工作是否有意义"**——
即若 $H$ 全部由 F3（孤岛无源）贡献，判据退化为连通性，整项工作的价值存疑。

## 评估结论：有意义，但机制论断是条件性的，须补三处

### 该质疑不成立的一半：拓扑结果由冷端动力学塑造

因果链为
冷端失效 → 机组跳闸（**顺序与时刻由机理模型决定**）→ 再调度 → 潮流转移
→ 线路过载 → 解列 → 孤岛无源 → 失电。

若 $H$ 只由拓扑决定、与冷端无关，则**机组跳闸时刻不应与 $H$ 相关**。
但 G1 跳闸时刻与 $H$ 的 $\rho = -0.7787$（$p = 1.72\times10^{-6}$）。
故 F3 判据虽是拓扑的，**哪些母线落入 F3 却由冷端动力学决定**。
这一条足以回应"结果平凡"的质疑。

### 该质疑成立的一半：本算例在结构上排除了电压崩溃

| 指标 | 值 |
|---|---|
| 系统负荷 / 装机 | 189.2 MW / 335 MW |
| **系统负载率** | **56.5%** |
| 容量裕度（剩余容量 − 剩余需发） | 中位 **70.3 MW**，最小 **0.0 MW**，**63 案无一为负** |

系统在**任何情景、任何阶段**都不存在发电容量不足。
电压崩溃是"系统接近负荷能力极限"的现象，而本系统在全部级联阶段都保有大量备用。
故 **F2b 数值端点从未出现（F2b≡0）是运行点与测试系统的性质，不是冷端失效级联的普适性质**——
这也是 F2b 从硬失供判据中移除、仅作披露的原因之一。

若不写明这一点，审稿人会认定 F2b≡0 是方法假象，
并以"结论是测试系统的产物"驳回。

### 一个已排除的伪发现（记录以免重犯）

容量裕度与 $H$ 的 $\rho = -0.627$（$p=3.7\times10^{-8}$），看似强预测因子。
但控制失效机组数 $n$ 后**全部不显著**：

| 层内 | $\rho$ | $p$ |
|---|---:|---:|
| $n=2$（15 案） | −0.309 | 0.262 |
| $n=3$（20 案） | −0.294 | 0.209 |
| $n=4$（15 案） | −0.353 | 0.196 |

裕度与 $n$ 的 $\rho = -0.811$——裕度只是**失效集规模的代理变量**。
**不作为发现写入论文。**
