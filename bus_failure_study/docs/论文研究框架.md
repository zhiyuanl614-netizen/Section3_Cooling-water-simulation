# 论文研究框架：冷端机理与冷源中断下的电网级联

> **范围确认**：论文保留原英文题目，聚焦两个研究问题：RQ1 解释湿冷冷端的运行机理及其形成的机组侧可用出力/跳闸信号，不分析电网后端级联；RQ2 基于该机理模型研究冷源中断下的电网级联影响。原先考虑的“大规模级联边界”暂不单列为 RQ。论文另加入冷端和电网侧参数敏感性分析，用于检验核心结果的鲁棒性。随附稿只借鉴论文组织方式，不迁移其 IEEE39、G33/G34、DC-OPF UAE、零滞后消融或任何数值结果。

## 一、题目与论文主张

### 保留原题目

**Mechanistic modeling of wet-recirculating cooling contingencies for cascading failure assessment in power systems**

题目保持不变。中文工作译名可写作：**湿式循环冷却系统故障的机理建模及其在电力系统级联失效评估中的应用**；不替换原英文题目。

### 一句话主张

本文首先建立并解释湿冷机组冷端的水量—液压—热力—保护运行机理，形成随时间变化的机组可用出力与跳闸信号；再将其用于冷源中断下的电网级联分析，揭示机组组合、退出顺序和网侧响应如何共同形成不同的服务损失后果；最后通过冷端与网侧参数扰动，检验主要机制和级联结论对参考参数选择的敏感程度。

**主线：冷端机理建模（RQ1）→ 冷源中断下的网侧级联评估（RQ2）→ 敏感性/鲁棒性检验（支撑 RQ1、RQ2，不另立 RQ3）。**

## 二、研究问题

### RQ1：湿冷冷端如何运行，冷却水状态如何影响机组可用出力？

补水中断后，池水库存、循环泵液压状态、循环水流量、冷却塔出口水温、凝汽器换热、饱和温度/背压和耗水如何耦合演化？这些冷端状态如何改变机组可用出力并最终触发保护？

**RQ1 的边界：** 讨论止于机组侧的冷端状态、`P_available(t)`、跳闸时刻和保护标签。RQ1 不讨论 H、频率最低点、UFLS、级联母线或最终电网服务损失；这些属于 RQ2。

- **命题 H1：** 机组退出不是单一固定降额率或固定延时，而是库存、水力和热力状态共同演化的结果；初始运行点和可用池容造成单位间差异。
- **主要证据：** P5 六机固定出力参考的单位级水池、流量、背压、温度、排热与蒸发轨迹；K1 六个独立单机情景作为机组侧对照。
- **解释边界：** P5 是固定故障前出力的冷端参考，不等于耦合 K1–K6 轨迹。P5 与 K0/K1–K6 的初始 Pg 并非所有机组完全一致，二者时刻差不能被无条件归因于“耦合效应”。

### RQ2：基于冷端机理模型，冷源中断会造成怎样的电网级联影响？

把 RQ1 生成的机组可用出力和冷端跳闸事件送入频率响应、受限再调度及 AC 级联后，单机和多机冷源中断如何影响电网频率、母线服务状态和切负荷？某台机组退出后的网侧响应又如何影响仍在断水机组的 Pg 和后续冷端轨迹？

- **命题 H2：** 多机同时断水不等于同时跳闸；网侧事件响应会改变幸存机组的出力及冷端负荷，因此机组退出顺序与级联后果取决于机组组合和事件链，而非仅由同时断水机组数决定。
- **主要证据：** K1–K6 的 63 个确定性基线情景；K2-G1-G2 的跨域同步时间序列；各情景的 H 母线集合、F1/F2a/F2b/F3、N 类别、频率、UFLS 和网侧静态切负荷。
- **解释边界：** 多情景比较是当前模型和指定 IEEE30 基态下的确定性结果。各 K 层级的情景占比只能称为“枚举集内占比”，不称概率或风险率。

## 三、概念框架：两个研究层次，一个模型接口

```text
RQ1：湿冷机组冷端机理（机组侧）
补水状态 / 初始 Pg / 水池锚点
       ↓
池水库存 → 泵流量/NPSH → 冷却水温 → 凝汽器排热与背压
       ↓
热力可用能力 / P_available(t) / 冷端保护标签与 t_trip
                       │
                       │ 机组可用出力与事件接口
                       ▼
RQ2：冷源中断下的电网级联（系统侧）
频率响应 → 受限再调度/UFLS → AC 事件断面级联 → 母线及负荷结果
                       │
                       └──更新幸存机组 Pg，反馈到其冷端轨迹
```

RQ1 单独解释冷端状态如何产生机组侧出力/跳闸信号；RQ2 才分析该信号在电网中的级联后果。冷端与频率/爬坡按时间推进，AC 电压和线路级联在事件断面求解；论文不应称其为全状态暂态联合仿真。

## 五、模型、接口和指标口径

### 5.1 RQ1：冷端模型

方法章节按当前代码实现和已审计输出介绍以下链路：

1. **水量库存：** 补水中断使外部补水供给为零；蒸发、排污、飘滴共同决定池水位变化。
2. **液压/循环流量：** 池水位改变泵静扬程与 NPSH 裕度，影响循环水可用流量。
3. **冷却与换热：** 流量、水温和热负荷决定塔/凝汽器换热状态、排热和背压变化。
4. **机组接口：** 热力可用能力与保护条件产生随时间变化的 `P_available(t)`、跳闸时刻与保护标签；该接口供 RQ2 使用。

主文只给当前模型真实实现且有证据支持的方程。单位锚点、保护阈值、补水响应、爬坡假设和数值步长可放入表格/附录。不得直接复制附件稿的 Ceff、UA、热容量、泵故障方程或参数值。

### 5.2 RQ2：电网级联耦合

- 频率响应、受限 Pg 爬坡及 UFLS 按事件推进。
- 网侧事件断面使用 AC 潮流和级联规则判定线路、孤岛和母线服务状态。
- 新的网侧出力回馈幸存机组的冷端模型；需展示这条反馈，不把冷端计算与电网计算简单并列。
- 明确区分：时域频率与再调度、事件断面 AC 级联、冷端秒级状态；不要将分层模型写成单一时间步长的连续暂态仿真。

### 5.3 结果指标

| 层面 | 指标 | 报告口径 |
|---|---|---|
| RQ1 冷端 | 水位、qcw、排热、蒸发/排污/飘滴、冷却水温、背压、热力能力 | 展示完整时序和机组差异；区分参考值与未校准假设 |
| RQ1 机组接口 | `P_available(t)`、冷端跳闸时间/顺序/标签 | 作为 RQ2 输入；不把机组跳闸时间直接当作电网级联规模 |
| RQ2 硬失供 | H=F3∨F2b，及母线集合 | 仅 F3/F2b 计入 H；F2b 是潮流不可解的模型服务代理 |
| RQ2 其他母线状态 | F1、F2a、F2b、F3 | 分开统计；F1/F2a 单独不等于硬失供 |
| RQ2 系统类别 | N0–N3 | 运行影响标签，不替代 H |
| RQ2 频率 | 最低频率、发生时刻、RoCoF、UFLS 量 | 与静态切负荷分别报告 |
| RQ2 负荷后果 | UFLS、网侧静态切负荷、总切负荷 | 单位 MW；不称 EENS/MWh |
| 全部情景 | 实际跳闸、删失集合、观察时间、停止原因、solver warning | 未观察到的后续跳闸不得写为已发生 |

## 六、敏感性分析与鲁棒性设计

敏感性分析作为 RQ1 与 RQ2 的支撑证据，检验冷端机理是否依赖单一参考参数，以及级联结论是否在合理模型扰动下保持。它不是概率分析，也不自动证明模型已现场校准。

### 6.1 冷端参数敏感性（支撑 RQ1）

建议优先选择有明确机理路径、且项目参数表/代码可调的参数组：

- **水量与库存：** 有效池容/面积、初始水位或正常—跳闸水位间距、补水中断后的供水可用比例（若模型支持）。
- **水力与热交换：** 冷却水流量能力、泵/NPSH 余量、塔逼近度/换热能力、凝汽器背压—可用能力曲线参数。
- **运行与响应：** 故障前 Pg、爬坡速率、补水响应/延时等现有假设。

RQ1 的敏感性输出：t_trip 与保护标签、跳闸顺序、关键轨迹（最低水位、qcw、最大背压/热力能力下降）和 `P_available(t)` 的变化。报告“参数变化导致的变化幅度/是否换序/是否换标签”，不要只给单一 trip-time 数字。

### 6.2 电网参数敏感性（支撑 RQ2）

在冷端参数保持基线、只改变一组网侧条件时，建议考察：

- **系统运行点：** 负荷水平或负荷分布、机组初始 Pg 与可用备用分布。
- **响应能力：** 爬坡率、再调度延时/能力、频率响应假设。
- **级联/保护规则：** 支路额定值/过载阈值、UFLS 定值或其它已实现保护规则；每次只改变明确的一组参数。

网侧输出包括 H 与 H 母线集合、H>0 状态是否改变、最低频率、UFLS、静态切负荷、总切负荷及 N 类别。H 母线数和切负荷 MW 需分开比较；不要把它们合并成未经定义的“风险分数”。

### 6.3 分层执行方案

1. **阶段 A：冷端单因素筛查。** 在 P5 和若干 K1 代表机组上，对选定冷端参数采用基准/低/高三个水平（优先用参数来源支持的范围；没有实测范围时明确写成 stress-test 水平），先检查保护机制、跳闸次序和 `P_available(t)` 是否稳定。
2. **阶段 B：网侧单因素筛查。** 固定冷端输入，在 K1–K6 基线中至少覆盖 H=0、H>0、较高 H、不同 K 和不同组合；先辨识哪些网侧参数会改变服务状态或排序。
3. **阶段 C：关键因素交互。** 对阶段 A/B 中影响较大的因素做小规模组合设计；重点检验冷端参数与电网备用/爬坡、负荷水平之间的交互。若组合计算资源允许，再扩展至全 63 案；不应只对个别案例敏感性计算后宣称全情景稳健。
4. **阶段 D：复核。** 对发生 H 状态翻转、H 母线显著变化、冷端保护标签/顺序改变及 solver warning 的案例，单独复跑或细化步长，并保留原始基线与扰动案。

### 6.4 鲁棒性判据与报告方式

- **机理鲁棒性：** 机制/保护标签是否保持；跳闸次序是否保持；t_trip、背压及能力轨迹变化多少。
- **级联鲁棒性：** H>0 是否保持；H 与 H 母线集合变化多少；频率/UFLS/静态切负荷是否改变；N 类是否转换。
- 对离散输出报告“保持/翻转的情景数”和逐案差异；对连续输出报告差值或相对变化范围，不计算没有概率权重的置信区间。
- 若只对代表情景做扰动，只能称“代表情景敏感性”；若要称“K1–K6 结论稳健”，应将关键因素复核扩展到完整枚举集或清楚限定范围。
- 参数扰动范围是模型敏感性设置，不是现场不确定性分布；无数据支撑时不做 Monte Carlo 概率结论。

## 七、拟定论文结构

### 1. Introduction

由湿冷机组依赖冷却水、冷端状态可能改变机组可用性切入。说明固定降额/直接切机难以展示冷端物理路径；继而指出冷源中断后的网侧级联需使用冷端生成的动态出力/跳闸信号评估。提出 RQ1（冷端机理）和 RQ2（级联影响），说明敏感性分析用于检验两部分主要结论的鲁棒性。

### 2. Methods

2.1 湿冷冷端系统边界、初始状态与方程；2.2 水池—泵—塔—凝汽器状态耦合与保护；2.3 从冷端状态到 `P_available(t)`/跳闸事件的接口；2.4 电网频率、再调度与 AC 事件级联；2.5 输出指标、停止/删失规则与数值审计。这里不单设 K6 first-H/continuation 的结果小节；K6 按常规基线情景纳入 K1–K6 结果表。

### 3. Archetype and experiment setup

**按用户要求，在 Methods 之后单独设置本章；本章不再安排 3.5 小节。**

3.1 **IEEE30 archetype and units：** IEEE30 基准网、6 台机组与冷端锚点、基准潮流及数据来源。

3.2 **Cooling-water contingency scenarios：** P5 固定出力冷端参考；K1 单机情景；K2–K6 组合矩阵及同时 t=0 补水中断协议；说明 first-H 端点与删失口径，但不在此展开 K6 continuation 结果。

3.3 **Coupled grid experiments：** 网侧时域频率/爬坡、事件断面 AC 级联、UFLS 和静态切负荷配置；说明模型边界与基线条件。

3.4 **Sensitivity and robustness experiments：** 冷端参数组、电网参数组、基准/低/高水平、代表案例筛选、关键因素交互与复核规则；写明哪些是已完成的基线、哪些是待补算的敏感性实验。

### 4. Results

4.1 **Cold-end operating mechanism and unit differences (RQ1)：** 用 P5 与机组级轨迹解释水位—流量—热交换/背压—保护的链路；限定结论于机组可用能力和跳闸。

4.2 **Event-level grid cascade and cold-end feedback (RQ2)：** 以 K2-G1-G2 等代表案例展示网侧事件前后 Pg、频率、背压/热力能力及后续冷端状态变化，解释“机组退出—电网响应—幸存机组冷端反馈”的时序链。

4.3 **Multi-scenario grid cascade outcomes (RQ2)：** 汇总 K1–K6 共 63 案的 H、频率、负荷后果和组合差异；报告硬失供母线、F1/F2a/F2b/F3、N 类、UFLS 与网侧静态切负荷，严格遵守删失和停止口径。此节与 4.2 分开，以避免把事件机理和跨案结果挤在同一节。

4.4 **Sensitivity and robustness analysis：** 在同一节内分别报告冷端参数扰动对保护标签、跳闸次序、t_trip、背压和 `P_available(t)` 的影响，以及网侧负荷/备用/爬坡/保护设定对 H、母线集合、频率、UFLS、静态切负荷与 N 类的影响；总结哪些机理/结论在已检验范围内保持、哪些会翻转。冷端与网侧敏感性不再拆成两个结果小节。

### 5. Discussion

讨论冷端机理模型相对固定降额/直接跳机表达的解释力；讨论事件驱动网侧反馈为何会造成不同组合结果；总结敏感性分析支持的稳健性与参数依赖性；说明模型对运行规划的启示及不可外推范围。K6 continuation 可留在项目审计/补充材料，除非作者决定它对主论证不可或缺，否则不作为独立主结果小节。

### 6. Limitations and conclusions

列明参考参数的现场验证不足、IEEE30 小系统、AC 级联为事件断面、保护/再调度规则简化、K4/K5 数值警告、确定性情景未加概率权重。结论逐条回答 RQ1/RQ2，并用敏感性结果限定鲁棒性表述；不宣称已发现普适的“大规模级联边界”，也不把模型输出称为现场事故预测。
