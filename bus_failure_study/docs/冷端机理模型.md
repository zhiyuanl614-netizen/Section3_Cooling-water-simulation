# 冷端机理模型与机组参数

## 研究对象与模型边界

每台机组各自配置一套湿冷冷端系统：集水池、循环水泵、冷却塔和表面式凝汽器。冷端内核以秒级定步长推进，慢变量为池水库存；泵流量、塔出口温度、凝汽器饱和温度/背压及功率修正构成冷却链路。补水中断后，库存持续下降，冷却能力恶化，直至保护动作。

当前 K1 的机组运行设定为：补水切断、运行期间不隔离排污、不执行水位触发的 SOP 降负荷；机组保持事件发生前实际出力，低水位保护动作时出力阶跃归零。其余机组按动态出力更新冷端负荷和补水需求。每个独立场景都从同一基准初态开始，不继承其他场景的冷却状态。

## 核心状态与过程

```text
池水位/有效库存
    → 循环泵扬程及 NPSH 可用裕度
    → 泵流量
    → 冷却塔出口水温
    → 凝汽器传热、饱和温度和背压
    → 蒸发/排污/飘滴耗水
    → 池水位持续下降
    → 低水位保护跳机
```

库存满足 $dV/dt=-(E+B+D)+M$；补水中断后 $M=0$。蒸发由排热量决定，排污由浓缩倍数的盐平衡决定，飘滴随循环水流量估算。泵、塔和凝汽器含一阶惯性；跳机条件按冷端内核的保护顺序判断。当前六台机组实际均由低水位首先触发。

不同机组的退出时间主要受故障前有功出力、耗水率和可用池容 $A(h_{normal}-h_{trip})$ 影响。机组容量本身不能代替运行出力；具体差异由锚点表中的逐机参数与 `basis` 来源说明控制。

## 参数及数据来源

- `data/coldend/unit_anchors.csv`：六机组冷端参数唯一事实来源，逐项保留取值依据。`pmax_mw` 来自 IEEE30，`pg0_mw` 应以基态潮流同步值为准；其余未实测参数均属模板/工程参考假设，不得称为现场校准值。
- `data/coldend/coupling_reference_assumptions.csv`：耦合运行假设唯一事实来源，包括爬坡、延时、补水容量/响应等。
- `src/coldend/model.py`：物理状态方程和单机仿真内核。
- `src/coldend/units.py`：从锚点 CSV 装配六套机组对象。
- `src/coldend/fleet.py`：P5 六机同时断水、固定故障前出力的独立冷端参考计算。

冷端模型原始内核保留，搬迁整理不修改其物理方程。冷端绘图脚本为 `src/coldend/plot.py`。

## P5 参考结果的定位

`results/reference/coldend_p5/` 保存六台机组同时断水、固定 $P_0$ 的冷端库存/退出序列基准，用于解释各机组冷端耐受时间，不是 K1 或 K2 的耦合网侧结果。顺序为 G13、G23、G2、G22、G27、G1；该目录保留汇总、事件流、逐机序列和图。K1/K2 的正式情景结果分别存放在 `results/K1/` 与未来的 `results/K2/`。
