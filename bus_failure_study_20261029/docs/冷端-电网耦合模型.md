# 冷端—电网耦合模型与运行入口

## 物理背景：区域共用水源与机组侧补水故障

六台机组（G1、G2、G13、G22、G23、G27）位于同一地区，冷端补水**取自同一 regional 水源**（水库/河网/水处理系统）。`data/coldend/unit_anchors.csv` 以 `makeup_source=regional_shared_reservoir` 记录该设定。

在此背景下，补水失效的物理机制是**机组自身的补水管线故障**，而非水源本身断供：`makeup_failure_mode=unit_makeup_line_break`。可能原因包括补水管线破损、阀门/止回阀失效、泵组故障或就地控制失电等。

因此：

- **机组级失效与机组级隔离**。一台机组补水管线故障只影响该机组，不影响同区其他机组取水；各机组仍经各自管路独立取水。
- **多机情景表示同时发生的多起独立机组级故障**，而非单一水源失效。K2–K6 的组合枚举刻画的是"多台机组同时出现补水故障"，其发生机制彼此独立。
- 该设定避免把"共用一个水源"直接等价于"一次故障同时切断全部机组"——真实的共因水源失效会使全部机组同时断水，属于另一类情景，不在本K1–K6 枚举集内。

各机组的冷端结构差异（池容、冷却塔逼近度、凝汽器清洁度）在 `unit_anchors.csv` 中独立给定，正是同一水源、同类故障下机组响应不同的物理来源。

## 模型接口与事件流程

冷端模型以机组实际有功出力 Pg(t) 为输入，推进排热、耗水、池水位、温度与保护状态；低水位保护达到条件后，将机组跳闸事件交给网侧模型。网侧再计算频率响应、受限爬坡再调度与事件断面的准稳态 AC 级联；幸存机组的新 Pg 再反馈给冷端模型。

```text
情景矩阵
  → 指定机组补水管线失效（补水中断）
  → 各机组独立推进冷端库存/热状态
  → 冷端保护触发并跳机
  → 频率响应、受限再调度与 AC 级联
  → 用更新后的 Pg 推进幸存断水机组
  → 下一次冷端跳机或到达规定停止条件
```

`src/coupling/coupled.py` 复用同一事件循环处理 K1 单机情景和 K2–K6 多机情景。K2–K6 所选机组的补水中断同时从 t=0 开始；实际跳机时刻由冷端状态及网侧再调度共同决定，并非将独立 K1 跳闸时刻简单拼接。正常供水随需水变化的响应常数不等于补水故障启动延时；故障源在 t=0 即置零。多机组合中各机组为彼此独立的补水管线故障（同一区域水源、各自取水），非单一水源共因失效。

频率、出力爬坡和冷端过程按时间推进；AC 电压与线路级联只在网侧事件断面求解，因此本模型不是全状态暂态联合仿真。

## 停止条件与 K6 双端点

K2–K6 的原始基线按 first-H/硬服务损失或已配置时域终点停止；K1 保留原六个独立单机事件结果。未在相应观察端点发生的所选机组跳闸仍按删失记录，不向后外推。

K6 保留两个互不覆盖的结果：

- `./run.sh K6`：原 first-H 基线，输出到 `results/K6/`。
- `./run.sh K6-full`：独立延续，输出到 `results/K6/continuation/`；跨过 first-H 后继续，遇到六台目标机组全跳、无在线机组、24 h 或孤岛潮流无解（F3）即停止。运行状态和数值警告在情景指标文档中单独记录。

## 频率保护与参数来源

耦合配置分为两份：`cfg_grid` 交给 CascadeSim，关闭静态级联内部的 UFLS/频率切机，避免与时域 SFR 重复；`cfg_freq` 交给 `simulate_frequency_ramp()`，保留 59.30/58.90/58.50 Hz 的时域 UFLS 档位。

爬坡、命令延时、正常补水能力/响应等参考假设唯一来源为 `data/coldend/coupling_reference_assumptions.csv`；机组冷端锚点唯一来源为 `data/coldend/unit_anchors.csv`。上述参数不是现场实测或校准值。
