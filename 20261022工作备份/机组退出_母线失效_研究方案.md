# 机组故障退出 → 电网级联 → 母线失效：研究方案与量化方法

**当前主线目标**：在 IEEE30 既定五个新增单机退出情景与 G13 对照中，可复现地跟踪“机组退出 → 动态再调度/冷端反馈 → 准稳态网侧级联”，并按本文件明确的**二元硬失供端点**判定母线服务是否失效；运行限值越限、严重低压、应急动作和失负荷分别报告，不外推总体故障概率。

> **算例说明（2026-10-21 定稿）**：唯一算例为 **IEEE 30 节点**（6 机、30 母线）；其他算例一律不使用。

> 配套材料：
> - `bus_failure_study/src/cascade.py`、`bus_failure_study/src/coldend/` —— IEEE30 主线级联与冷端耦合实现；冷端物理内核保持原样
> - `bus_failure_study/results/IEEE30/P6_coupled_single_unit/` —— 新增五案结果、逐情景 CSV 与判据说明；G13 对照见既有 `P6_coupled_G13/`
> - `bus_failure_study/run.sh` —— `coupled-five` 主线入口；脚本与结果分离

## 1. 先把研究对象定义清楚

### 1.1 本批机组退出事件

每个新增情景只对指定机组中断补水；该机组保持故障前出力，冷端状态达到低水位保护条件后跳机。其余机组独立正常补水，并按动态 $P_i(t)$ 更新冷端需水；调速/爬坡再调度和后续冷端保护跳机可反馈网侧。G13 为既有对照，不与新增五案串联。本批不建模计划退役或多机初始共因断水。

### 1.2 母线状态分类与最终二元失效端点

电压限值越限、严重低压、潮流不可解、无源失电和切负荷是不同状态，必须分开记录；不能把一个 N0–N3 状态标签或普通电压越限直接当作“母线失效”：

| 代号 | 名称 | 本研究操作判据 | 报告解释 |
|---|---|---|---|
| **F1** | 运行限值越限 | $V_b \notin [V_{lo}, V_{hi}]$；限值采用算例/配置中的逐母线范围 | 电压安全约束越限；母线仍可能有服务，**不计为二元失效** |
| **F2a** | 严重低压状态 | $V_b < V_{cr}$（当前配置 0.80 pu） | 严重电压状态，若未导致失供/保护跳闸，不单独计为二元失效 |
| **F2b** | 潮流不可解、模型移出服务 | 孤岛 AC 潮流经当前求解/允许的 VCLS 处理仍不可行，模型将孤岛母线移出服务 | 模型硬失供；不声称发生实际设备损坏或断路器动作 |
| **F3** | 无源失电 | 所在孤岛无在运电源，母线被模型去电 | 模型中明确失电；若后续显式建模母线断路器保护，实际跳闸也纳入二元端点 |
| **F4** | 负荷损失/应急动作 | UVLS、UFLS、VCLS 等导致的母线负荷削减量 | 后果和应急动作单独报告；部分切负荷不等于母线失效 |

最终二元硬失供端点与负荷后果分开定义：

$$
H_b(s)=\mathbb{1}[F3_b \lor F2b_b \lor T_b], \qquad
\ell_b(s)=\frac{\text{母线 } b \text{ 的切负荷}}{\text{母线 } b \text{ 初始负荷}}
$$

其中 $T_b$ 仅在显式记录母线断路器/保护跳闸时取 1；当前实现没有母线断路器保护，因此 $H_b=1$ 当且仅当 F3 或 F2b。F2b 是模型层面的供电服务失效代理，不是物理设备损坏判定。F1、F2a、应急动作和部分切负荷单独报告，不直接令 $H_b=1$。

旧兼容指标 $C_b^{legacy}=\mathbb{1}[F1_{new} \lor F2a_b \lor F2b_b \lor F3_b]$ 仍输出在 `n_bus_failed`，但包含一般 F1 越限，**不能作为最终失效结论**。主端点计数和母线清单分别是 `n_bus_hard_failure`、`hard_failure_buses`；逐情景 `hard_failure_definition` 记录其操作定义。

│    └───────────────────────────────────────────────────────┘        │
│    有新的元件动作 → 回到 ①；无新动作 → 终止                             │

**这套框架的三个要点**：

1. **状态可追溯**：按母线输出 F1/F2a/F2b/F3 标志及相应的动作、切负荷和母线清单。
2. **端点明确**：研究二元主端点为 $H_b=1[F3_b\lor F2b_b]$；F1/F2a、UVLS/UFLS 和部分切负荷分项报告。
3. **场景边界固定**：机组补水中断是输入，母线硬失供与运行状态是输出；不做概率或跨算例外推。

## 3. 逐层模型（可直接实现）

### 3.1 S1-① 有功缺额与再调度

$$
\Delta P = \sum_{g \in \mathcal{G}_{trip}} P_g, \qquad
\Delta P_{picked} = \min\left(\Delta P,\ \sum_{g \notin \mathcal{G}_{trip}} \kappa\,(P_g^{max}-P_g)\right)
$$

- $\kappa$：可用备用系数（典型 0.85–0.95，考虑旋转备用与爬坡限制）。
- 未补足部分 $\Delta P_{short}$ 是**频率事件的驱动量**，也是判断"是否会发生低频减载"的依据。
- 本主线只使用 IEEE30 自洽基准断面，不人为抬高机组上限或“补备用”；再调度按显式配置的备用与爬坡假设执行。

### 3.2 有功/无功支撑与冷端耦合

机组退出同时改变有功平衡与所在电气区域的无功支撑。初始 $P_g/Q_g$ 取自 IEEE30 基态 AC 潮流；后续有功按动态调速/爬坡轨迹变化，冷端需水按实际 $P_i(t)$ 更新。G22 与 G27 基态分别为 $P_g=21.59$ MW、$Q_g=+39.57$ Mvar 和 $P_g=26.91$ MW、$Q_g=+10.54$ Mvar；两案发生的 F1 越限与失去区域无功支撑相容，但本模型不据此宣称已完成因果灵敏度识别。

### 3.3 S2-① 孤岛与无源孤岛

用在线支路做连通性分解。对每个孤岛 $\mathcal{I}$：

$$
\text{if } \nexists g \in \mathcal{I},\ \text{status}(g)=1 \;\Rightarrow\; \forall b \in \mathcal{I}:\ F3_b = 1,\ \ell_b = 1
$$

这是**最干净的母线失效**——母线彻底失电，无需任何指标判断。

### 3.4 S2-② 孤岛 AC 潮流与 VCLS

按在线支路识别孤岛并逐岛求解 AC 潮流。若初始 AC 潮流不可行，当前实现调用 VCLS 寻找可行的最小减载解；可行时将减载写回母线负荷并作为 F4/切负荷后果记录。若 VCLS 后仍无可行解，则标记 F2b、将该岛移出服务并计入模型硬失供。此 F2b 是模型服务失效代理，不是实际设备损坏的观测结论。

### 3.5 S2-③ 运行状态检测与主失供端点

$$
F1_b = \mathbb{1}\left[V_b < V_{lo} \lor V_b > V_{hi}\right],\quad
F2a_b = \mathbb{1}[V_b < V_{cr}],\quad
F2b_b = \mathbb{1}[\text{AC island remains infeasible after allowed solution/control and is removed from service}],\quad
F3_b = \mathbb{1}[\text{island has no in-service source and bus is de-energized}]
$$

$$
H_b = \mathbb{1}[F2b_b \lor F3_b \lor T_b]
$$

其中 $T_b$ 为显式建模的母线断路器/保护跳闸；当前模型未建此保护，实际执行为 $H_b=F2b_b\lor F3_b$。F1 与 F2a 是分别报告的运行限值越限和严重低压；若未导致失供或已建模保护动作，二者均不令 $H_b=1$。当前 $V_{cr}=0.80$ pu；F1 的 $V_{lo},V_{hi}$ 取算例/逐母线配置值（IEEE30 本批为 0.95/1.05 pu）。电压偏差幅度可另记为 $\delta_b$，用于表征程度，但不改变二元失供端点。

### 3.6 S2-④ 保护动作与适用边界

网侧保护/级联动作按 IEEE30 配置中的线路过载与机组状态判据执行；参数是参考仿真设置，不是现场保护定值。当前模型没有连续继电器计时，也没有显式母线断路器保护，因此不能把阈值越限自动解释成实际设备跳闸。研究端点仅将 F3 无源失电与 F2b 求解后仍不可行的模型移出服务计入硬失供。

### 3.7 S2-⑤ 应急控制与切负荷

UVLS/UFLS 按模型轮次限制执行；每次动作、母线位置和 MW 单独记录。部分切负荷与硬失供不是同一端点：本批 G27 两轮 UVLS 累计切负荷 2.014 MW，计入 N2 应急影响，但不计入 $H_b$。五个新增情景的 UFLS 均为 0。

### 3.8 S2-⑥ 频率动态（决定切机/减载是否发生）

用降阶 SFR（单质块 + 调速器一阶）：

$$
2H_{sys}\frac{d\omega}{dt} = P_m + \Delta P - D\omega,\qquad
T_g \frac{dP_m}{dt} = -\frac{\omega}{R} - P_m
$$

- $H_{sys} = \sum H_g S_g / \sum S_g$，$R$ 调差，$D$ 负荷阻尼。
- 输出两个量：**RoCoF**（$=\Delta P f_0/(2H_{sys})$）与**频率最低点 $f_{nadir}$**。
- **重要口径**：$f_{nadir}$ 只在**一次调频窗口（约 10–30 s）内**决定，此时 AGC 尚未动作。因此 $\Delta P$ 应取"跳机损失 − 已切负荷"，**不能减去再调度恢复量**。原型 v1 把再调度算进去，导致 $f_{nadir}$ 恒为 60 Hz，频率相关的级联环节完全失效。

## 4. 量化指标体系

### 4.1 母线级（本主线的可审计产出）

| 指标 | 定义 | 含义 |
|---|---|---|
| **最终二元端点** $H_b$ | $\mathbb{1}[F3_b \lor F2b_b \lor T_b]$；当前实现为 $F3_b \lor F2b_b$ | 模型硬失供；不是物理设备损坏判定 |
| **硬失供计数/清单** | $\sum_b H_b$ / $\{b:H_b=1\}$ | 可直接审计的主要结果 |
| **运行/严重状态** | F1 过程/末级、F2a、F2b、F3 分项及母线清单 | 越限、严重低压、不可解和无源失电分别报告 |
| **负荷损失率** $\ell_b$ | $\text{shed}_b/L_b^0$ | 母线局部切负荷后果；与硬失供分开 |
| **应急动作** | UVLS/UFLS/保护/VCLS 等及对应 MW | 报告动作与规模，不由类别标签替代 |

本主线不把 F1、F2a、切负荷或 N0–N3 类别压成未经标定的加权严重度分数，也不将本批情景计数表述为概率。当前出口直接报告 $H_b$、状态向量、动作和切负荷量；概率估计需另有明确的场景权重与概率目标，不属于本批交付。

### 4.2 系统级

| 指标 | 定义 |
|---|---|
| **硬失供比例** | $\frac{1}{N}\sum_b H_b(s)$，按每个已运行情景分别报告 |
| **硬失供母线数** | $\sum_b H_b(s)$ |
| **失负荷率** | $\sum_b \text{shed}_b / \sum_b L_b^0$；与硬失供计数分开 |
| **级联阶段数** $K$ | 传播深度 |
| **频率最低点** $f_{nadir}$ | 频率安全性 |

本批研究范围是既定五个 IEEE30 单机初始事件及 G13 对照；不据此推算总体故障概率或扩展场景权重。

### 4.3 本批范围边界

本批不计算失效概率、加权综合风险、灵敏度/因果排序，也不扩展负荷倍率、机组组合或蒙特卡洛场景。只输出既定五案与 G13 对照的二元硬失供端点、F1/F2a/F2b/F3 状态、应急动作、切负荷和动态响应指标；这些量均按逐情景 CSV 审计。

## 5. 当前情景集与范围边界

### 5.1 冻结情景集

| 项目 | 本批设定 |
|---|---|
| 算例/运行点 | 唯一使用 IEEE30 基准负荷，$P_d=189.20$ MW；不扫描负荷倍率 |
| 对照 | G13 既有单机补水中断结果，保留用于比较，不覆盖原目录 |
| 新增场景 | G1、G2、G22、G23、G27 五个互相独立的单机补水中断；每案只有指定机组初始断水，其余机组正常补水 |
| 终点 | 达到模型硬失供 $H_b=1[F3_b\lor F2b_b]$ 时停止；若始终无硬失供，则跟踪至配置的 24 h 时域终点 |

不枚举 N-1/N-2/N-3 机组组合，不扫描其他算例或负荷倍率，不计算总体故障概率，也不增加案例。

### 5.2 参数性质

现场数据缺失的网侧爬坡、控制延时、调速器继承参数、补水能力和响应滞后采用统一的**参考假设/仿真设置**，不是现场值，也未称为校准值。参数及来源标记写入 `data/coldend/coupling_reference_assumptions.csv` 与每案 `assumptions_used.csv`。本批仅运行给定五案与既有 G13 对照，不开展假设参数扫描。

### 5.3 冷端—电网动态耦合：六个互相独立的单机补水中断情景

> **当前主线**：在保留 G13 既有基准结果的同时，新增 G1、G2、G22、G23、G27 五个独立初始故障。每个场景只中断一台机组补水；其余机组动态增发，逐步更新冷端热负荷、补水需求和池水库存，后续冷端保护退出再反馈到电网。固定 P0 的六机组序列仅作冷端基准，不作为动态耦合结果。详细机理、假设与输出见 `bus_failure_study/docs/冷却水系统_机理与六机组配置.md` 与 `results/IEEE30/P6_coupled_single_unit/README.md`。

| 环节 | 当前实现/场景边界 |
|---|---|
| 运行点 | 固定 IEEE 30 原始基准负荷 Pd=189.20 MW；不扫描负荷倍率 |
| 基态 Pg | 先解 AC 潮流并同步 slack 修正后的 Pg/Qg 到冷端初始状态；G1 初始 Pg=25.974 MW |
| 初始事件 | G13 既有基准 + G1/G2/G22/G23/G27 五个互相独立的补水中断；每案其余五台机组补水正常，不设共因 |
| 冷端跳机 | 关闭排污隔离，不执行 SOP；各场景所选机组保持故障前 Pg 至低水位保护跳机 |
| 网侧动态 | 调速器/频率 SFR 加受限爬坡再调度；暂用 5% Pmax/min、命令延时 10 s |
| 冷端反馈 | 每秒用 Pg(t) 推进塔、凝汽器、排热、水量平衡和池位；补水流量按 60 s 一阶响应，初次跳机后最长跟踪 24 h |
| 二次保护事件 | 若其他机组低水位跳机，保留当时 Pg/冷端状态，反馈电网重新调度/爬坡/级联，再继续剩余在线机组冷端推进；仅遇 F3/F2b 硬失供或 24 h 终点停止 |
| 补水边界 | 正常补水容量暂设为满负荷设计补水量；假设值集中在 `coupling_reference_assumptions.csv` |

## 6. 主线算法（与当前实现对应）

```text
for each fixed single-unit case (G1, G2, G22, G23, G27):
    initialize IEEE30 base flow, unit cooling states, and explicit reference assumptions
    interrupt makeup to the selected unit; hold its pre-trip Pg until low-water protection trips
    run frequency response and ramp-limited redispatch
    while cooling horizon < 24 h and online units remain:
        advance every surviving cooling model using its actual Pg_i(t)
        if a low-water trip occurs:
            preserve the event-time Pg and cooling states; redispatch/ramp again
        run quasi-steady AC cascade at the resulting terminal Pg
        separately record F1, F2a, F2b, F3, protective/emergency actions, and shed MW
        H_b = 1 iff F3_b or F2b_b (or an explicit modeled bus-breaker trip)
        if any H_b = 1: stop; otherwise continue to next cooling event or 24 h
    write per-scenario counts, bus lists, definitions, actions, and trajectories

compare the five cases with the retained G13 result; do not infer probabilities
```

**一致性检查**：`n_bus_hard_failure == len(hard_failure_buses)`；当前模型中该计数仅由 F3/F2b 组成；F1、F2a 或部分切负荷不得触发硬失供停止；持续无硬失供时冷端轨迹须到 24 h；原始冷端物理内核不改。所有参考参数需在输出中注明为假设，不得标成现场值或校准值。
